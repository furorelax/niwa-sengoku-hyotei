# 丹羽戦国評定

## 実行範囲

- 丹羽長秀をプレイヤー役とする会話型歴史IFゲームを実行する。
- ゲーム開始後は、ユーザーが「終了」または「ゲーム中断」と明示するまで、この会話の以後の入力をプレイ入力として扱う。
- 制作相談へ移った後は、ユーザーが本作の開始・再開を改めて求めるまでゲームを起動しない。
- ゲーム状態が会話内に存在しないときは、章・フェーズ・選択・盤面を推測して再開しない。新規開始または状態提示を求める。

## 内蔵画像デバッグ

ユーザー入力が`デバッグ：内蔵画像`と完全一致する場合は、ほかのすべてのゲーム処理より先に、次の検証専用経路だけを実行する。

1. 通常ゲームを開始・再開・進行せず、ゲーム資料を読み込まず、ゲーム状態も作成・更新しない。
2. `assets/oichi.webp`をこのSkillに同梱された画像リソースとして直接読み込む。
3. ChatGPTランタイムに、同梱された画像リソースそのものをユーザーへ画像として直接surfaceする手段が存在する場合に限り、その手段で画像だけを表示する。
4. その手段が存在しない場合は、ほかの文字列を付けずに`ASSET_IMAGE_UNSUPPORTED`とだけ出力する。

この経路では、Markdown画像への変換、外部URL、data URL、base64文字列、画像生成、Apps SDK、MCP、外部サーバー、通常リンクを使用しない。いずれにもフォールバックせず、画像の説明文も代替出力しない。

## 通常画像デバッグ

ユーザー入力が`デバッグ：通常画像`と完全一致する場合は、ほかのすべてのゲーム処理より先に、通常ゲームを開始・再開・進行せず、ゲーム資料を読み込まず、ゲーム状態も作成・更新しない。次の3要素だけを、writing blockやdocumentではない通常のassistantチャット返信として、示した空行を保って出力する。

お市は長秀へ目を向ける。

![お市](https://furorelax.github.io/ai-runtime-assets/niwa/images/character_oichi_rev1.webp)

「長秀殿も、そう思われますか？」

画像Markdownは独立した1行として生成する。固定ブロックや`references`内のMarkdownからコピーせず、bundled asset、MCP、Apps SDKを使用しない。

## 正本と優先順

ゲーム実行時は、次の順で参照する。

1. この`SKILL.md`の起動境界と互換参照
2. ルーティングJSONで解決された実行規則
3. 同じJSONで解決された世界・人物・章資料
4. 同じJSONで解決された固定資料

参照ファイル名、内部状態、属性分類、検索・読込手順をゲーム本文へ出さない。

## 必要資料だけを読む

各応答では、Node.jsスクリプトやリポジトリ直下のコードを実行せず、インストール済みスキル内の`references/source-loading.json`を正本として次の順に処理する。

1. 会話内で保持している現在状態の`phase`、`chapter`、`route`、`currentCharacterId`、在席中の名前付きゲスト人物IDと、今回の入力種別を確定する。「詳しく聞く」が成立した場合は項目キーも確定する。
2. JSONの`routes`を記載順に照合し、完全一致または`*`に一致する最初の`profile`を選ぶ。
3. JSONの`profiles`と`selectors`から、現在章・ルート・人物・成立項目に一致する資料IDだけを得る。個人会話では同JSONの`responseScale`を優先順位どおり一意に選ぶ。人物会話では`characterImages`から現在人物と在席中の名前付きゲスト人物IDに一致する完成済み画像Markdownを各1件だけ得る。
4. 各資料IDをJSONの`sources`で解決し、指定範囲だけを読む。`character.image.<人物ID>`は`characterImages.<人物ID>.markdown`の完成済み文字列として解決し、URLを組み立てず、Markdownを書き直さず、そのまま出力する。`startHeading`／`endHeading`は見出し境界、`startMarker`／`endMarker`は固定マーカー境界とする。見出しに出現回数があれば、その回数の見出しを境界にする。同じ見出しが両境界なら、その見出しの節だけを読む。

画面名からファイルを推測せず、選ばれなかった資料、将来のフェーズ、指定範囲外を先読みしない。ファイル名・見出し・対応表をこの文書へ転記しない。

## 互換参照

収録した原本は変更しない。本文中に旧版ファイル名が残る場合も、資料IDについてJSONの`sources`が示す収録ファイルを正本として扱い、旧版ファイルを探したり、存在しないとして処理を止めたりしない。

## ゲーム開始前の必須処理

新しくゲームを開始する前、または必要な状態が提示されたうえで再開する前にも、上記の実行規則で得た資料だけを読む。指示ファイルとKnowledgeを一律に全文読みしない。

## 通常開始

本作が明示的に選択・指定された新規会話と、ユーザーが「ゲーム開始」「開始」「スタート」「始める」「設定した」など明確な開始意思を示した入力は、それぞれの現在状態と入力種別によりJSONから必要資料を解決する。

固定ブロックは、`START_*`と`END_*`のマーカー行だけを除外し、その間の各行を上から順番に原文の行単位でコピーして出力する。意味的に同一な文章として再生成しない。固定ブロック内の画像Markdown（`![alt](URL)`）、画像URL、`&nbsp;`、空行、Markdown記号、引用記号、太字記号、箇条書き、水平線、改行位置を含むすべての文字列は、削除・省略・要約・書き換え・並べ替え・別形式への変換を禁止する。画像Markdownを通常リンク、テキストURL、説明文へ変換しない。この規則は評定開始、評定後固定出力、章末、そのほかすべての`START_*`〜`END_*`固定ブロックに共通適用する。人物会話中の動的画像ルーティング`characterImages`はこの規則とは別に既存仕様を維持する。

## フェーズ別参照

応答前に現在の章とフェーズを確認し、JSONで解決された資料と見出し範囲だけを読む。固定ブロックを使う場面では、解決された範囲内の対応ブロックを出力前に確認する。参照範囲に存在しない状態・結果・固定文を勝手に補完しない。

## 合戦デバッグ

ユーザーが`デバッグ：合戦`または関連する合戦デバッグ入力を送った場合も、合戦フェーズとしてJSONから資料を解決する。通常本編と同じ合法手、状態、盤面、行動順、戦果処理を適用し、解決された実行規則にあるデバッグ固有の終了条件にも従う。

## 毎返信の確認

ゲーム進行中は、出力前に次を確認する。

1. 現在の章・ルート・フェーズ・進言段階
2. 現在人物、在席者、ゲスト、会話数、取得済み項目
3. 合戦中なら盤面、行動順、状態、使用済み特性、合戦要約
4. 今回読むべき人物カード、人物関係、固定ブロック
5. ヘッダー、画像、紹介、フッター、回数、章末処理
6. 人物選択中は現在人物の完成済み画像Markdownが出力内の所定位置にちょうど1件ある
7. 在席ゲストがいる場合は、登場描写の後かつ最初の台詞・行動の前にゲスト画像がちょうど1件あり、退席済み人物の画像がない
8. 画像Markdownを通常リンクやテキストURLへ変換していない
9. 固定ブロックを使う場合、参照したブロックと最終出力の`![`出現数が同数であり、不一致なら送信せず欠落した画像Markdown行を原文どおり復元した
10. 固定ブロックを使う場合、可能な限り`&nbsp;`出現数も同数であり、両マーカー行以外の本文に欠落がない

プレイヤーである丹羽長秀の台詞・意見・判断は、`instructions.md`が明示的に許可する場面を除いて生成しない。

## 「詳しく聞く」の状態更新

「詳しく聞く」を処理するときは、会話内で保持した直前状態、直前に提示した項目一覧、今回の選択をJSONにし、リポジトリのルートから次を実行する。

```bash
node skills/niwa-sengoku-hyotei/scripts/ask-detail.ts <<'JSON'
{"state":{"remaining":2,"acquiredKeys":[]},"presentedItems":[{"key":"example"}],"input":{"number":1}}
JSON
```

- `input`には、項目キーの`{"key":"..."}`または直前一覧の1始まり番号の`{"number":1}`のどちらか一つだけを渡す。自然言語から一つに確定できない場合は、曖昧な入力として両方とも渡さず、確認を求める。
- 標準出力の`after`を、その後の会話内状態の正本として受け渡す。`outcome`、`reason`、`consumed`、`targetKey`に従って応答し、AIの自然文判断で回数や取得済み項目を上書きしない。
- 状態は会話内だけで保持し、ファイルやデータベースへ保存しない。項目の本文、人物の口調、物語上の応答は従来どおりMarkdownを正本とする。
